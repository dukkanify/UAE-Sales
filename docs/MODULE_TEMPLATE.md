# Module documentation template

Every substantial module should document:

## Purpose

One paragraph: what problem this module solves.

## Dependencies

Internal packages/services and external providers.

## Public APIs

Routes, exported functions, events/webhooks.

## Configuration

Env vars, feature flags, platform settings keys.

## Usage examples

Minimal snippets for the common happy path.

## Maintenance notes

Known limitations, ownership, related tech-debt IDs.

---

Existing module docs live under `docs/` (e.g. `COURSE_MANAGEMENT.md`, `MOBILE_API.md`, `OPS_SUPPORT.md`). Prefer updating those over inventing parallel READMEs unless a new domain is introduced.
